# CLAUDE.md — Art in LA

Project context for Claude Code. Read this first. The narrative changelog of how
the project got to its current state lives in `PROJECT_STATUS.md`.

## What this is

A community-maintained map + calendar of **museum and non-commercial art
institution** exhibitions and events across Los Angeles County. Static React +
Vite site on GitHub Pages, fed by Python scrapers that run on a daily GitHub
Actions cron and commit fresh JSON data.

- Repo: `github.com/birdofnofeather/art-in-la`, default branch `main`.
- Live site: `https://birdofnofeather.github.io/art-in-la/`
- Scope: **nonprofit art AND performing-arts institutions** (Round 11). Commercial
  galleries and for-profit promoters are excluded. **114 venues** (92 art /
  22 performing), each with exactly one scraper: 56 bespoke modules in
  `scrapers/venues/` + config-driven ones from `scrapers/generic_venues.yaml`.

## Layout

```
public/data/      venues.json (hand-curated) + events.json, archive.json,
                  scraped_venues.json, warnings.json, health.json (ALL generated by CI)
scrapers/         base.py (BaseScraper + 6 strategies), registry.py (active list),
                  run_all.py (orchestrator), utils/, venues/<id>.py (one per venue)
scrapers/venues/_archived_galleries/   retired gallery scrapers (NOT imported)
src/              React app: App.jsx, components/, lib/ (data, filters, constants)
.github/workflows/ daily-scrape.yml (cron) + deploy.yml (Pages)
commit.ps1        one-command commit+push helper (Windows)
```

## Conventions and decisions (do not regress these)

### Scope: no commercial galleries; art vs. performing arts
Commercial galleries were removed (Bergamot Station too, Round 11). Their
scrapers live in `scrapers/venues/_archived_galleries/` (not imported).
Every venue has `discipline: visual | performing`, assigned by its PRIMARY
facility and core programme: performing = built around a stage (music,
theater, dance, spoken word — e.g. REDCAT, Pieter, JACCC, Luckman, Beyond
Baroque, LA Phil, CTG); visual = exists mainly to exhibit art (its talks,
screenings and concerts still count). The header switch Art · Performing arts ·
All filters everything by it (default Art). Venue `type` values:
`museum | community | alternative | academic | theater | music | center`.
Regions were consolidated 11→9 (see `src/lib/constants.js` REGION_LABEL).
**Do not drop existing venues** unless confirmed closed or commercial.

### Dates & times: LA-local, never shifted
Everyone (venues + audience) is in Los Angeles. `scrapers/utils/dateparse.py:to_la_iso`
is the single source of truth, and `Event.to_dict()` runs every event through it.
On the frontend, `src/lib/filters.js:parseDate` parses the stored LA wall-clock
fields verbatim (no viewer-timezone conversion) so every visitor sees the same
times the venue's own site shows — do not replace it with bare `new Date(s)`:
- A real time keeps the source wall-clock; if the source tags it UTC, it is
  converted to the equivalent LA time (so it matches what the venue's site shows).
- A value at midnight in its own timezone is a **date-only** listing → returned as
  a bare `YYYY-MM-DD` (all-day). **Never fabricate a `00:00` / "12:00 AM" time.**
- There is no other timezone conversion anywhere.

### Recurring tours filtered
`scrapers/utils/recurring.py` drops standing recurring programmes, including
architecture / garden / gallery tours (e.g. Getty "Art, Architecture, and Garden
Tour"). Real one-off curator/exhibition tours are kept.

### HTTP
`scrapers/utils/http.py` sends a desktop-Chrome User-Agent because several venue
sites (Norton Simon, Armory) 403/429 a bot UA. Keep it browser-like. The Chrome
version is DERIVED FROM THE DATE (`_chrome_major`): a hard-coded "Chrome/124"
went ~30 months stale and USC/UCLA firewalls began resetting connections —
USC Fisher, USC Pacific Asia Museum and Fowler produced nothing from Sept 1,
2026 until fixed. A connection reset is retried once with a Safari UA.

### CI runners: pinned to ubuntu-24.04 (do not change to ubuntu-latest)
`ubuntu-latest` became 26.04, for which Playwright has no Chromium build; the
browser install is continue-on-error, so rendering silently stopped. A failed
browser install now opens a "Headless browser missing" issue.

### Rendered venues + snapshots
JavaScript-built calendars have bespoke parsers on `venues/_rendered.py`
(`render_page` → `custom_parse`): la_phil + ford_theatres (shared platform),
la_opera, geffen_playhouse, cerritos_center. Parsers are written against real
source fetched FROM GITHUB'S RUNNERS: Actions → "Snapshot venue pages" → venue
ids → pages land on the `debug-snapshots` branch (never main).

### Parallel scraping
`run_all.py` scrapes venues concurrently via a thread pool (`SCRAPE_WORKERS` env,
default 8); a full run is ~27s. Output is deduped + sorted afterward, so order is
stable. Set `SCRAPE_WORKERS=1` to debug sequentially.

### Frontend (Round 11)
Tabs: **Events / Exhibitions / Map / Venues / Saved** (+ About; Archive via
`#tab=archive`). Default tab Events, default date preset Next 7 days.
Exhibitions tab is hidden in the Performing view. ONE shared filter set across
tabs (`filters` in App.jsx). FilterBar: search + Filters button always visible;
date chips + Free + Family in one swipeable row; event type / area / venue type
/ custom dates in a bottom sheet (phones) or inline panel (desktop). The map
works on mobile, frames the visible venues (outliers excluded) and shows only
venues with something matching the current filters. Basemap: OpenStreetMap
tiles (CSS-muted) with automatic fallback to Esri light grey — CARTO now
requires a paid key, never re-add it. `lib/data.js` de-dupes venues by id.

### New event fields (generated by scrapers)
`is_free` (true/false/null — never guessed false from absence), `price_text`
("Free" / "$10" / "$10–$25"), and `audience` (subset of `family`, `teen`) are
populated in `scrapers/utils/{pricing,audience}.py` from JSON-LD `offers` /
`isAccessibleForFree`, the Tribe REST `cost`, and keyword fallbacks. See SCHEMA.md.

### Per-venue default event type
`BaseScraper.default_event_type` (default "other") is the type assigned when the
text classifier finds no keyword. Venues whose programming is one format override
it — e.g. Academy Museum sets `default_event_type = "screening"` so bare film
titles classify correctly. This is what keeps the "other" bucket small (~14%).

### Hygiene gate + calendar feeds
`scrapers/utils/validate.py` runs on the upcoming list before publish, dropping
null-start non-exhibitions, stale undated exhibitions (>45-day grace), and
already-ended records (logged to warnings.json). `scrapers/utils/feeds.py` writes
subscribable `public/data/feeds/{all,free,family}.ics` each run (CRLF preserved
via `.gitattributes -text`; committed by daily-scrape.yml).

### Generated data + git
`events/archive/scraped_venues/warnings.json` are rewritten daily by CI. `.gitattributes`
marks them `merge=ours` so pull/rebase auto-resolves them; line endings are LF.
`venues.json` is the only hand-curated data file.

## Curation rules live in ONE file (do not regress this)

`scrapers/rules.yaml` is the single source of truth for every decision about
*what counts as what*: the event-type list and their keywords, which recurring
programmes are hidden, what makes something an exhibition, audience tags, and
the text-quality rules. **No keywords in Python.** `utils/{event_type,recurring,
audience,validate}.py` and `base.py` all read from it via `utils/rules.py`.

Every rule carries `examples:` — `match:` titles it should catch, `reject:`
titles it must not. `python -m scrapers.check_rules` runs them all and CI fails
if any disagrees. The `reject:` half is what stops a deliberate exclusion
(Getty's garden tour, LACMA's gallery tours) being weakened to make a venue's
count look healthier. See `.github/RULES_ARE_OFF_LIMITS.md`.

## Harvest and classification are separate (do not regress this)

`public/data/raw_events.json` holds the untouched harvest — everything ever
scraped, upcoming and past, pruned at 2 years. `scrapers/classify.py` turns it
into `events.json` + `archive.json` by applying the rules.

Consequence: **a rules change is retroactive.** Edit `rules.yaml`, run
`python -m scrapers.reclassify` (or `--dry-run` first), and every event we have
ever stored — including the archive — is re-labelled in seconds with no
scraping. Before this split an event's type was frozen at scrape time and a
taxonomy change could only affect future scrapes.

A type the venue itself published (Getty's category field, LA Plaza's section,
Academy Museum's Contentful type) is recorded as `_asserted_type` and beats
text inference — but falls back to the text if that type is later retired from
`rules.yaml`. `base.py` detects an asserted type by checking whether the
scraper's type differs from what reading the text would give, so none of the
46 scrapers needed editing.

## Recurring detection is by RHYTHM, not by count

`utils/recurring.py` catches a standing programme two ways: by name (the
`drop_patterns` in rules.yaml) and by rhythm — the same title at regular
intervals. The old count-based rule (5+ occurrences) missed Pieter's weekly
dance classes, which appear exactly 4 times, plus 78 other records fleet-wide.
Cadence requires gaps of **at least 3 days**, so a three-night theatre run
(REDCAT) stays visible while weekly/monthly programmes are caught.
A series can be `drop`ped or `collapse`d (keep the next date, note the rest).

## Text is repaired before publication

`utils/text.py:normalise` fixes UTF-8-read-as-Latin-1 corruption ("espaÃ±ol"
→ "español"), normalises Unicode and collapses whitespace. Six Getty events
were live with mangled Spanish; nothing checked. Quality rules in rules.yaml
now have a `severity`: `drop` never publishes, `warn` publishes and records the
problem on the record as `_quality_notes` for the status page.

## Squarespace venues read their own JSON feed

`utils/squarespace.py` + the `squarespace` strategy in `base.py`: any
Squarespace page returns its data at `?format=json`, and an Events collection
puts real events under `upcoming`/`past` with proper timestamps, links, images
and addresses. Covers pieter (47, HTML parser found 24), molaa (15, found 9),
bergamot_station (9, had no scraper), mak_center, las_fotos_project. The other
11 Squarespace venues use a plain `page` collection and have no feed.
Set `squarespace = False` on a subclass to opt out.

## Exhibitions: a second harvest pass

`exhibitions_url` on a scraper triggers a second pass over that page, forcing
`event_type = "exhibition"`. **Only URL-reading strategies run in that pass** —
wp_tribe and the iCal probe address the site ROOT and ignore the path, so
pointed at /exhibitions they return the ordinary events feed and every event
gets republished as a fabricated exhibition (five venues did this in testing).
A venue needing bespoke parsing overrides `custom_parse_exhibitions`.

Status: the plumbing is in and costs nothing, but a survey of all 85 venues
found **no venue with a structured exhibitions feed**. 26 venues still publish
events and zero exhibitions (LACMA, Hammer, Huntington, Autry, Skirball, JANM,
Fowler, MOLAA…). Closing that gap needs the LLM extraction tier.

## Exhibitions merge by (venue, title)

A scraper that reads "on view now" and stamps today's date creates a fresh
record every run — MOCA's MONUMENTS accumulated 31 copies, five MOCA shows 150
between them. `classify.merge_exhibitions` collapses them to one record
spanning the widest reported range. Exhibitions are also EXEMPT from the
recurring filter: an exhibition is a date range, not a repeated occurrence, and
without the exemption a long-running show is mistaken for a standing programme
and vanishes.

## Harvest merge rule (do not regress this)

`run_all` replaces a producing venue's UPCOMING records wholesale (so a
cancelled event disappears) but KEEPS its past records forever — a venue's site
stops listing an event once it has happened, so a past record can never be
re-harvested. Replacing everything wholesale took the archive from 757 records
to 203 in one run.

## Knowing whether it works: three witnesses (do not regress this)

`scrapers/monitor.py`. You cannot detect breakage by examining your own output
— you need something independent to compare against. Three checks per venue,
green only when all three agree:

1. **The source page.** How many UPCOMING dates does the venue's page
   advertise? Compared against what we HARVESTED, never what we published —
   curation deliberately removes things (Pieter publishes 4 of 47). Only future
   dates are counted; venues list past events below upcoming ones, so a raw
   date count marks healthy venues broken daily.
2. **Recent history.** `health.json` keeps `recent_counts` (last 14 runs). A
   collapse short of zero (armory 44 → 4) never trips a zero check.
3. **A written expectation.** `scrapers/expectations.json` — regenerate with
   `python -m scrapers.baseline`. Entries marked `"source": "human"` are never
   overwritten. **21 museums have a hand-set `min_exhibitions`**, which is what
   makes the exhibition gap visible: LACMA showing 0 exhibitions is now a daily
   yellow instead of looking healthy.

**Triage matters:** a venue whose site is unreachable is YELLOW ("their
problem"), not RED. Several venues block datacenter IPs and work from GitHub
runners; pointing an automated repair at those produces confident wrong changes
to code that was never broken.

Output: `public/data/status.json` + a GitHub Actions step summary table.

## The fleet gate: a bad run never reaches the site

`scrapers/utils/fleet.py` runs before publishing and compares against the last
published state. It BLOCKS the publish (leaving yesterday's data live, exit
code 1) on: no events at all, duplicate/missing ids, event count falling >35%,
>6 producing venues going dark at once, the archive shrinking >10%, or any
non-exhibition without a start date. A rise only warns.

Per-venue checks catch one venue breaking; this catches the shared machinery —
a rules.yaml edit, a date bug — damaging everything at once, which no
per-venue check can see. Exit code 1 means "refused, deliberately" and
daily-scrape.yml treats it as a safe outcome, not a crash.

## Freshness heartbeat

`.github/workflows/freshness.yml`, on a separate schedule (15:00 UTC vs 07:00)
so one broken workflow cannot hide the other. Checks the committed data, not
what the scrape says about itself: is `scraped_at` under 36h old, did the last
run refuse to publish, are there at least 20 events. Opens/closes an issue.
This exists because the daily scrape failed silently from June 1 for ten days
and the site looked fine the whole time.

## Bot-gated venues: headless-browser render path

Two venues serve an event-less shell (or a hard 429) to plain HTTP clients but
hand a real browser the full calendar once their anti-bot JS runs:
- `norton_simon` — Cloudflare; the SPA renders events client-side.
- `huntington` — Vercel "Security Checkpoint" (429) that **self-clears after a
  few seconds if you wait in-page** instead of re-navigating.

Both are now scraped via `scrapers/utils/render.py`, which runs
`render_cli.py` (headless Chromium / Playwright) in a **subprocess** — keeping
the thread-unfriendly browser work out of the scrape thread pool, the same way
the Getty scraper shells out to Node. The renderer is deliberately minimal:
spoof only `navigator.webdriver` + `window.chrome` (piling on more navigator
overrides made Vercel's checkpoint stick), wait the interstitial out in-page,
then return the populated HTML. CI installs it via `requirements-render.txt`
+ `playwright install --with-deps chromium`. If Playwright is absent (a plain
local run), these two scrapers no-op and the rest of the pipeline is unaffected.


### Alerts
daily-scrape.yml opens/updates a "Scraper health alert" issue (emails the
owner) when a venue is RED or the run refused to publish, and a failure issue
if the job fails.

## Reading tiers and self-healing (Round 11 — do not regress)
Strategy chain per URL: wp_tribe → squarespace → ical → jsonld → eventbrite →
feed → custom → **generic** → **llm**. Exhibitions pass (`exhibitions_url`,
from the scraper OR venues.json): squarespace → jsonld → feed →
custom_parse_exhibitions → generic → llm.
- `utils/generic_listing.py`: title+date "card" reader. Opt-in per venue
  (`heuristic: true` in generic_venues.yaml) ONLY after its output was checked
  by hand. Guards: junk titles, dates glued to titles, past/stale years,
  year-less dates that would be pushed into next year.
- `utils/llm_extract.py`: Claude Haiku 5.5 (`claude-haiku-5-5`, $0.10/$0.50
  per M tokens) via the anthropic SDK, structured JSON output. Content-hash
  cache (`scrapers/state/llm_cache.json`, re-read at most every 21 days if
  unchanged), hard monthly budget `LLM_MONTHLY_BUDGET_USD` (=3 in CI) metered
  into `scrapers/state/llm_ledger.json`, ≤150 calls/run. JavaScript-built pages
  (little text, or nothing found) are re-read after rendering in headless
  Chromium (`utils/render.py`, CI only, ≤25/run). Output is kept only if
  each title appears verbatim on the page and its day-of-month appears near
  it. No key → silent no-op; such venues show YELLOW "waiting", not RED.
- Tier 1 self-healing: the llm strategy runs when every parser returns nothing,
  and also when output collapses below 30% of the venue's median recent count.
- Tier 2: `.github/workflows/repair-scraper.yml` + `scrapers/repair_plan.py` —
  after a bespoke scraper is silent 4+ runs (tier 1 failed too) and the site
  is reachable, an agent (claude-sonnet-5-5) edits ONLY that module; kept only
  if tests, check_rules and a live dry-run scrape pass. Max 2 runs/month,
  21-day cooldown per venue, each fix its own revertable commit.

## Repair verification
`python -m scrapers.verify_venue <id>` is the gate for the tier-2 repair agent:
live scrape (parser only), full curation, and PASS only if published titles
are real, dates plausible and curation didn't discard most of the harvest.

## Frontend extras (Round 11b)
Share button on every event/exhibition (`lib/share.js`, `ShareButton.jsx`);
`#event=<id>` opens it with filters cleared and highlights it. Card actions
are 36px icon buttons. WCAG 2.2 AA verified with axe-core on all tabs, phone
and desktop (ink text ≥65% opacity, accent #456a8a, yellow "LA" on an ink
badge). Feeds: internal `feeds/art.ics` + `feeds/performing.ics` only.

## Performing-arts runs
`utils/runs.py` (called in classify.derive): at performing venues, the
performances of one production collapse into ONE record (`_run: True`,
`run_count`, `recurrence_note` "N performances · Nov 4 – Nov 29"), folding
variants ("(Opening Night)", "Passing Strange WINE WEDNESDAY"). Only when
dates cluster (median gap ≤ 3 days) — weekly classes are left to the recurring
filter; venues with `venue_overrides: drop` (Pieter) are never bundled. Runs
are exempt from the recurring filter and the >4-day one-off hygiene rule.

### Academy Museum showtimes
`scrapers/venues/academy_museum.py` reads exact session times from the Ticketure
API (`tickets.academymuseum.org/api/events/{ticketureIdProduction}/sessions`,
UTC) — the listing-page dict is keyed by that same id. Contentful `audienceType`
maps to audience tags; `nonTicketedProgram` → price_text "Free". The old
detail-page HTML time-parse remains as fallback only.

## Running it

```bash
# Frontend
npm install && npm run dev            # http://localhost:5173
npm run build

# Scrapers
pip install -r scrapers/requirements.txt
python -m scrapers.run_all            # all venues, writes public/data/*.json
python -m scrapers.run_all --only ica_la --dry-run   # one venue, no write
python -m scrapers.run_all --skip-scrape             # re-classify, no network

# Curation rules
python -m scrapers.check_rules        # do the rules match their own examples?
python -m scrapers.reclassify --dry-run   # what would a rules edit change?
python -m scrapers.reclassify             # apply it to ALL data, incl. archive

# Tests (no network, fast)
pip install pytest && python -m pytest scrapers/tests -q

# Monitoring
python -m scrapers.baseline           # write/refresh expectations.json
python -m scrapers.baseline --show lacma
python -m scrapers.run_all --no-probe # skip the source-page comparison

# Bot-gated venues (Norton Simon, Huntington) — needs the headless browser:
pip install -r scrapers/requirements-render.txt && python -m playwright install chromium
python -m scrapers.run_all --only norton_simon,huntington --dry-run
```

Commit + push (Windows): `.\commit.ps1 "message"` (validates JSON, stages,
commits, rebases, pushes).

## LLM tier is live

$0.034. The monitor uses the LLM's reading as a second opinion: if it examined
a venue page and found nothing upcoming, a raw date count on that page is past
or undated listings → YELLOW, not RED (`monitor._llm_found_nothing_upcoming`).
